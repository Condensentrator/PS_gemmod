# 宝石工房 · 分类原则与内容扩展路线

> 结论先行：**只分到矿物大类（刚玉、绿柱石、石英…），颜色作为变体标签，不再单独占物种。**
> 新内容靠"新矿物 + 新颜色配方 + 新机器/新交易"来加，不靠堆 item id。

---

## 1. 分类模型

### 1.1 三层，而不是四层

```
矿物大类（物种）
  └─ 颜色变体（标签）
       └─ 重量阶段（小/中/大/巨）
```

- **矿物大类**：刚玉、绿柱石、石英、尖晶石、碧玺……每种对应一个晶核；
- **颜色变体**：同一矿物在不同培养液成分下长出的颜色（红/蓝/绿/黄/粉…）；
- **重量阶段**：小/中/大/巨，只影响占格、贴图和价格。

### 1.2 为什么不再按颜色拆物种

- 按颜色拆会变成 **颜色数 × 4 阶段** 的物品爆炸（现在 3 色 × 4 = 12 件）；
- 颜色应该是"配方结果"，不是"新物品"；
- 玩家真正关心的是：**这块刚玉是什么颜色、多大、值多少**，而不是它是不是一个独立 id。

### 1.3 数据怎么落

- 每个矿物/阶段一个 id：`gem_corundum_cultured` / `_m` / `_l` / `_xl`；
- 颜色存标签：`GEM_COLOR = red / blue / green / yellow / pink ...`；
- 显示名动态设置：红 → 红宝石，蓝 → 蓝宝石，绿 → 绿色蓝宝石，黄 → 黄色蓝宝石……
- 价格 = 矿物基础价 × 颜色系数 × 重量；
- 每颗宝石仍有 `GEM_UID_*` 唯一标签，避免同 id 堆叠；
- 旧 id（`gem_ruby_cultured` 等）保留为兼容别名，不再新增。

> 贴图：一个矿物一套阶段图标即可；颜色可以用 `ItemSpriteModifier` 着色，或在图标上做颜色变体。
> 即使颜色暂时只体现在名字/描述上，也不影响玩法验证。

---

## 2. 往后加内容的原则

每加一块内容，最好满足下面至少一条，否则只是"多一个 id"：

1. **新配方**：新的水质成分组合 → 新颜色/新变体；
2. **新决策**：机器档位/模组让玩家在"快 vs 好、便宜 vs 稀有"之间选；
3. **新循环**：鉴定、切割、镶嵌、委托、拍卖，让已有物品产生新用途；
4. **新风险**：裂晶、爆釜、假货、违禁、识破；
5. **新目标**：图鉴、收藏、成就、天赋、限定色。

## 3. 内容扩展路线

### P1 — 分类收敛（下一步，小改）
- 把刚玉的颜色从"三个物种"合并成"一个刚玉物种 + 颜色标签"；
- 红/蓝/绿继续由水质成分决定，显示名不变；
- 旧物品通过 id 别名继续可用。

### P2 — 第二个矿物：绿柱石（验证管线）
- 物种：绿柱石（beryl）；
- 颜色：祖母绿（绿）、海蓝宝石（蓝）、摩根石（粉）；
- 水质映射：植物/有机 → 绿；矿物/铜 → 蓝；锰 → 粉；
- 需要新晶核 `gem_core_beryl`；
- 目的：验证"一种矿物 + 多颜色 + 一套阶段"的扩展流程，确认以后加矿物只需要改数据表。

### P3 — 水质化学加深
- 新增掺杂剂物品：铬、铁、钛、锰、铜等（可当作矿盐/添加剂）；
- 酸碱度（`ACID`/`BASE`）影响生长速度与裂晶率；
- 稳定剂/还原剂/漂白剂进入配方；
- 不同水源（锈水、幽水、沟渠、纯净）有各自的成分画像；
- 目的：让"配培养液"成为真正的玩法，而不是看一个纯度数字。

### P4 — 机器与模组
- 温控、压力舱、稳压器、催化槽、过滤循环；
- 退火/稳定化模组（陈化线）；
- 自动投料/自动收菜（后期自动化）；
- 目的：用模组而不是新机器来扩展深度，保持"2 台机器 + 模组"的结构。

### P5 — 经济与 NPC
- 宝石商人：按颜色/重量/品质收购；
- 鉴定师：鉴定培育货、识别假货；
- 委托：客户要"3 克拉以上、蓝色、无瑕"的宝石，完成给溢价；
- 拍卖/展览：高品质宝石的溢价渠道；
- 违禁/走私：毒晶、假货、洗白。

### P6 — 原石与切割
- NPC 卖原石，切割随机出宝石 + 少量晶核；
- 鉴定：原石可能在切开前未知；
- 假原石/染色石：低概率骗局；
- 目的：给"培育"之外一条快钱+赌的平行线。

### P7 — 首饰与长期目标
- 裸石 + 金属 → 戒指/吊坠/胸针；
- 图鉴/收藏册：记录见过的矿物、颜色、尺寸；
- 成就/天赋：鉴定师、培育师、珠宝商；
- 季节/事件：限定色、稀有原石、拍卖会。

---

## 4. 加一个新矿物的清单

1. 定义矿物：名字、基础价、颜色表、难度（是否需要高压/催化）；
2. 定义颜色 → 水质成分的映射（例如铜 → 蓝，锰 → 粉）；
3. 加一个晶核 `gem_core_<mineral>`；
4. 加 4 个阶段物品（小/中/大/巨）或复用通用阶段 id + 矿物标签；
5. 给颜色定名字与价格系数；
6. 生成图标（一套阶段图标即可，颜色可后续做着色）；
7. 加入商人供货/配方来源；
8. 用三种测试水验证颜色判定。

---

## 5. 当前测试包怎么对应

- 现在已有的红/蓝/绿三套物品，可以理解为"刚玉的三种颜色变体"；
- 下一步 P1 会把它们合并为一个刚玉物种 + `GEM_COLOR` 标签；
- 在那之前，继续用现有三套物品测试水质成分判定也完全没问题。

---

## 6. 建议的下一步

先做 **P1（刚玉合并颜色）+ P2（绿柱石）**：
- P1 把物品模型收敛到"矿物 × 颜色标签"，以后加颜色不再加 item；
- P2 用绿柱石验证"新矿物"只需要数据表和晶核，不需要改生长主逻辑。

这两步做完，后续加石英、尖晶石、碧玺就都是填表工作了。

## 7. 颜色表现：最终采用预染色 + 换物品

运行时染色试过三种方案，最终都放弃：

- `ItemSpriteModifier`：是叠加精灵，不是染色；
- 纹理乘色 + 取图补丁：在 UI 上不生效；
- `GameItemElement.Validate` + `Image.color` + `ToggleBackground`：测试核能染，但实际物品 UI 刷新会重置，不稳定。

**最终方案**：离线生成每种矿物×颜色的阶段图标，物品 id 也按颜色拆分：

- 刚玉：`gem_corundum_{red|blue|green|yellow|pink}_cultured` × 4 阶段；
- 绿柱石：`gem_beryl_{emerald|aqua|morganite|heliodor}_cultured` × 4 阶段；
- 生长逻辑只选择"矿物 + 颜色"，然后生成对应 id；
- UI 不需要改颜色，稳定、无额外性能开销；
- 代价是物品/图标数量增加，但扩展仍然是填表。
